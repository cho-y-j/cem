## 1. 프로젝트 개요

### 1.1 프로젝트 배경

건설 현장에서 운영되는 다양한 임대 장비와 관련 인력을 효율적으로 관리하기 위한 통합 플랫폼입니다.

**해결하고자 하는 문제:**
- 장비 및 인력 관리의 비효율성
- 반입 승인 프로세스의 복잡성
- 실시간 현황 파악의 어려움
- 안전 관리 및 긴급 상황 대응의 부재
- 작업 확인서 및 정산의 수작업 의존

### 1.2 프로젝트 목표

✅ **효율적인 장비·인력 관리**
- 장비 및 인력 등록, 서류 관리, 상태 관리 자동화

✅ **체계적인 반입 요청 프로세스**
- Owner → BP → EP 3단계 승인 프로세스

✅ **실시간 위치 추적 및 모니터링**
- GPS 기반 위치 추적 (5분 간격)
- 작업 현황 실시간 모니터링

✅ **안전 관리 및 긴급 상황 대응**
- 안전점검 시스템
- 긴급 알림 전송 및 해결 처리

✅ **근로기준법 준수**
- 휴식 시간 자동 체크 (4시간 이상 경고)

## 2. 시스템 아키텍처

### 2.1 전체 아키텍처

```
┌─────────────────────────────────────────────────────────┐
│                    Frontend (React 19)                    │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │   Desktop    │  │   Mobile     │  │   Inspector  │  │
│  │   (Web)      │  │   (Worker)   │  │   (Mobile)   │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
└─────────────────────────────────────────────────────────┘
                        ↕ tRPC (Type-Safe API)
┌─────────────────────────────────────────────────────────┐
│              Backend (Express + tRPC 11)                  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │   Routers    │  │   Auth       │  │   Storage    │  │
│  │   (tRPC)     │  │   (JWT)      │  │   (S3)       │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
└─────────────────────────────────────────────────────────┘
                        ↕ Drizzle ORM
┌─────────────────────────────────────────────────────────┐
│         Database (PostgreSQL - Supabase)                 │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │   Tables     │  │   Storage    │  │   RLS        │  │
│  │   (20+)      │  │   (Files)    │  │   (Security) │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 2.2 데이터 흐름 패턴

**Type-Safe Full-Stack Architecture:**

1. **Schema Definition** (`drizzle/schema.ts`)
   - 데이터베이스 스키마의 단일 소스
   - Drizzle ORM으로 TypeScript 타입 자동 생성

2. **Database Layer** (`server/db.ts`)
   - 모든 데이터베이스 쿼리 중앙화
   - snake_case ↔ camelCase 자동 변환

3. **API Layer** (`server/routers.ts`)
   - tRPC 프로시저 (타입 안전 API 엔드포인트)
   - 역할 기반 접근 제어 (RBAC)

4. **Frontend** (`client/src/`)
   - tRPC 클라이언트로 타입 자동 생성
   - React Query로 데이터 페칭

### 2.3 역할 기반 접근 제어 (RBAC)

시스템은 **6가지 사용자 역할**을 지원합니다:

| 역할 | 영문명 | 설명 | 주요 권한 |
|------|--------|------|-----------|
| **관리자** | Admin | 시스템 전체 관리 | 모든 기능 접근, 마스터 데이터 관리 |
| **장비임대사업자** | Owner | 장비 및 인력 소유 | 장비/인력 등록, 반입 요청 생성 |
| **시공사** | BP | 반입 요청 1차 승인 | 반입 요청 승인, 작업 확인서 승인 |
| **발주처** | EP | 반입 요청 최종 승인 | 최종 승인, 전체 현황 모니터링 |
| **작업자** | Worker | 현장 작업 수행 | 작업 확인서 제출, GPS 위치 전송 |
| **안전점검원** | Inspector | 안전점검 수행 | 안전점검 기록, NFC 태그 스캔 |

### 3.2 반입 요청 프로세스

**3단계 승인 워크플로우:**

```
Owner (장비임대사업자)
  ↓
  1. BP 회사 선택
  2. 장비 및 인력 선택
  3. 서류 검증 (필수 서류 체크)
  4. 반입 목적, 투입 예정일, 철수 예정일 입력
  5. 반입 요청 제출
  ↓
BP (시공사)
  ↓
  1. 반입 요청 확인
  2. 장비 및 인력 서류 검토
  3. 작업계획서 업로드
  4. EP 회사 선택
  5. 승인 또는 반려
  ↓
EP (발주처)
  ↓
  1. 반입 요청 확인
  2. 작업계획서 검토
  3. 최종 승인 또는 반려
  ↓
반입 완료 ✅
```

**주요 기능:**
- ✅ 서류 자동 검증 (필수 서류 체크)
- ✅ 작업계획서 업로드 및 관리
- ✅ 전자서명 (Canvas 기반)
- ✅ 상태별 필터링 및 조회
- ✅ 반입 요청 취소 기능 (BP)

### 3.3 투입 관리 및 작업확인서

#### 투입 관리
- ✅ 투입 등록 (Owner)
- ✅ BP 투입 승인 워크플로우
  - Owner → Deployment (pending_bp) → BP 승인 → Active
- ✅ 장비 및 인력 선택
- ✅ 작업 유형 선택 (일대/월대/O/T/철야)
- ✅ 유도원 지정
- ✅ 작업 구역(WorkZone) 설정
- ✅ 단가 정보 관리
- ✅ 투입 이력 조회

#### 작업확인서 (Work Journal)
- ✅ 운전자 작업 확인서 제출
- ✅ 유도원 작업 확인서 제출
- ✅ BP 작업 확인 및 서명
- ✅ 월별 정리표
- ✅ 상태별 필터링

### 3.4 GPS 기반 출근 체크 시스템

**주요 기능:**
- ✅ GPS 좌표 기반 출근 체크
- ✅ 작업 구역(WorkZone) 관리
  - 원형 구역 (Circle)
  - 다각형 구역 (Polygon)
- ✅ 구역 내/외 출근 여부 자동 판단
- ✅ 출근 현황 모니터링 페이지
- ✅ 필터 기능 (BP 회사, Owner 회사, 사용자 종류, 이름, 날짜)
- ✅ 통계 카드 (총 출근자, 구역 내/외 출근, 생체 인증)
- ✅ 시간대별 분포 (오전/오후)

- Google Maps 연동으로 지도에서 직접 구역 설정

```
┌─────────────┐
│   Owner     │
│  (장비임대)  │
└──────┬──────┘

       │    - BP 회사 선택

       │    - 반입 정보 입력

┌─────────────┐
│     BP      │

└──────┬──────┘
       │ 2. 반입 요청 승인
       │    - 서류 검토
       │    - 작업계획서 업로드
       │    - EP 회사 선택
       │    - 승인/반려
       ↓
┌─────────────┐
│     EP      │
│  (발주처)    │
└──────┬──────┘
       │ 3. 최종 승인
       │    - 작업계획서 검토
       │    - 최종 승인/반려
       ↓
┌─────────────┐
│  반입 완료   │
└─────────────┘
```
