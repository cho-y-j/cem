## 🐛 발견된 문제

### 1. 긴급 알림 데이터 조회 실패
- **증상**: http://localhost:3000/emergency-alerts 페이지에서 긴급 알림이 표시되지 않음
- **원인**:
  - `getEmergencyAlerts()` 함수가 Supabase FK join을 사용하려 했으나 FK 관계가 설정되지 않음
  - Supabase PostgREST 에러: `PGRST200 - Could not find a relationship`
- **영향**: 데이터베이스에 25개의 긴급 알림이 있었지만 화면에 표시되지 않음

### 2. 중복된 Router 정의
- **증상**: 긴급 알림 API가 작동하지 않음
- **원인**:
  - `server/routers.ts` 파일에서 `emergency` router가 2번 정의됨
  - Line 1276: 올바른 `emergencyRouter` import
  - Line 1479-1558: 오래된 inline router (빈 배열 반환)
  - JavaScript 객체 특성상 나중에 정의된 것이 앞의 것을 덮어씀
- **영향**: 정상적인 router가 동작하지 않고 빈 배열만 반환됨

### 3. 지도 로딩 실패
- **증상**: 긴급 알림 지도가 "For development purposes only" 워터마크와 함께 제대로 로드되지 않음
- **원인**:
  - 커스텀 `GoogleMap` 컴포넌트가 API 키를 제대로 인식하지 못함
  - `NoApiKeys` 에러 발생
- **영향**: 지도가 표시되지만 사용하기 불편함

### 4. 여러 긴급 상황 구분 불가
- **증상**: 여러 긴급 알림이 발생했을 때 지도에서 어떤 것이 어떤 것인지 구분하기 어려움
- **원인**: 모든 마커가 동일한 빨간색 아이콘으로 표시됨

### 1. 데이터베이스 쿼리 수정

**파일**: `server/db.ts` (lines 2727-2788)

**변경 내용**:
- Supabase FK join 방식 제거
- 수동 데이터 조합 방식으로 변경

**Before**:
```typescript
const { data, error } = await supabase
  .from('emergency_alerts')
  .select(`
    *,
    workers:worker_id (id, name, phone),
    equipment:equipment_id (id, reg_num)
  `)
  .order('created_at', { ascending: false });
```

**After**:
```typescript
// 1. 긴급 알림만 먼저 조회
const { data: alerts } = await supabase
  .from('emergency_alerts')
  .select('*')
  .order('created_at', { ascending: false });

// 2. 필요한 worker_id와 equipment_id 수집
const workerIds = [...new Set(alerts.map(a => a.worker_id).filter(Boolean))];
const equipmentIds = [...new Set(alerts.map(a => a.equipment_id).filter(Boolean))];

// 3. Workers 정보 별도 조회
const { data: workers } = await supabase
  .from('workers')
  .select('id, name, phone')
  .in('id', workerIds);

// 4. Equipment 정보 별도 조회
const { data: equipment } = await supabase
  .from('equipment')
  .select('id, reg_num')
  .in('id', equipmentIds);

// 5. Map으로 조합
const workersMap = new Map(workers.map(w => [w.id, w]));
const equipmentMap = new Map(equipment.map(e => [e.id, e]));

return alerts.map(alert => ({
  ...alert,
  workers: workersMap.get(alert.worker_id) || null,
  equipment: equipmentMap.get(alert.equipment_id) || null,
}));
```

**효과**:
- ✅ 25개 긴급 알림 정상 조회
- ✅ Worker 및 Equipment 정보 정상 결합
- ✅ FK 제약조건 없이도 작동

## 💡 기술적 인사이트

### 1. Supabase FK 관계 문제
- **문제**: Supabase PostgREST가 자동으로 FK 관계를 찾지 못함
- **원인**: FK constraint가 제대로 설정되지 않았거나 명시적인 fkey 지정 필요
- **해결**: 수동 데이터 조합으로 FK 제약조건 우회
- **교훈**: 복잡한 관계는 수동 join이 더 안정적일 수 있음

### 2. JavaScript 객체 속성 덮어쓰기
- **문제**: 같은 키로 여러 번 정의하면 나중 것이 앞의 것을 덮어씀
- **원인**: JavaScript 객체 특성
- **해결**: 중복 정의 제거
- **교훈**: 대규모 파일에서는 중복 정의 주의 필요

### 3. Google Maps 라이브러리 선택
- **문제**: 여러 Google Maps 라이브러리가 존재
- **해결**: 프로젝트 내에서 일관된 라이브러리 사용
- **교훈**: `@vis.gl/react-google-maps`가 안정적이고 사용하기 쉬움

### 4. 지도-목록 연동 패턴
- **구현**: State로 선택된 항목 관리
- **효과**: 사용자가 직관적으로 위치 파악 가능
- **교훈**: 시각적 피드백이 중요함 (강조, 애니메이션)
