# 작업일지 2025-11-17

## 투입 관리 목록 표시 문제 해결

### 문제 상황

1. **화면에 목록이 아무것도 안 나옴**
   - Owner, BP, EP 모든 화면에서 투입 목록이 0개로 표시
   - 서버는 6개의 deployment를 찾았으나 프론트엔드에는 0개 전달

2. **유도원 버튼 권한 문제**
   - Owner가 유도원 추가/교체 버튼을 볼 수 있었음
   - Owner는 유도원 관리 권한이 없어야 함 (BP만 가능)

3. **EP 장비 표시 확인**
   - EP가 반입/출입 요청에서 본인 회사가 승인한 장비들만 보임
   - 이것은 **정상 동작**임 (버그 아님)

### 원인 분석

1. **JOIN 쿼리 오류**
   ```
   Could not find a relationship between 'equipment' and 'equipment_types'
   Hint: Perhaps you meant 'equip_types' instead of 'equipment_types'
   ```
   - 복잡한 중첩 JOIN 쿼리가 Supabase에서 에러 발생
   - 테이블명 오류: `equipment_types` → `equip_types`
   - 필드명 오류: `type_name` → `name`

2. **데이터 변환 문제**
   - JOIN으로 가져온 중첩 객체가 toCamelCase 처리 중 문제 발생
   - 서버에서는 6개 찾았지만 프론트엔드에 0개 전달됨

### 해결 방법

#### 1. JOIN 방식 제거 (server/db.ts)

**Before:**
```typescript
let query = supabase
  .from('deployments')
  .select(`
    *,
    equipment:equipment!deployments_equipment_id_fkey(id, reg_num, equip_type:equip_types(id, type_name)),
    worker:workers!deployments_worker_id_fkey(id, name, phone, worker_type:worker_types(id, type_name)),
    guide_worker:workers!deployments_guide_worker_id_fkey(id, name, phone, worker_type:worker_types(id, type_name))
  `)
```

**After:**
```typescript
// 1. 기본 deployment만 조회
let query = supabase
  .from('deployments')
  .select('*')
  .order('created_at', { ascending: false });

// 2. Equipment 별도 조회
const { data: equipment } = await supabase
  .from('equipment')
  .select(`
    id,
    reg_num,
    equip_type_id,
    equip_type:equip_types!equipment_equip_type_id_fkey(id, name)
  `)
  .in('id', equipmentIds);

// 3. Workers 별도 조회
const { data: workers } = await supabase
  .from('workers')
  .select(`
    id,
    name,
    phone,
    license_num,
    worker_type_id,
    worker_type:worker_types!workers_worker_type_id_fkey(id, name)
  `)
  .in('id', allWorkerIds);

// 4. deployments에 데이터 부착
deployments.forEach(deployment => {
  if (deployment.equipmentId && equipmentMap.has(deployment.equipmentId)) {
    (deployment as any).equipment = equipmentMap.get(deployment.equipmentId);
  }
  if (deployment.workerId && workerMap.has(deployment.workerId)) {
    (deployment as any).worker = workerMap.get(deployment.workerId);
  }
  if (deployment.guideWorkerId && workerMap.has(deployment.guideWorkerId)) {
    (deployment as any).guideWorker = workerMap.get(deployment.guideWorkerId);
  }
});
```

**장점:**
- 단순하고 안정적
- 에러 없이 확실하게 동작
- 각 데이터를 독립적으로 조회하여 부착

#### 2. 필드명 수정

**equip_types 테이블:**

**worker_types 테이블:**

### 기술적 교훈

1. **복잡한 JOIN보다 단순한 쿼리가 낫다**
   - Supabase PostgREST의 중첩 JOIN은 복잡하고 에러에 취약
   - 별도 쿼리 + Map 방식이 더 안정적

2. **실제 DB 스키마 확인 필수**
   - 추측하지 말고 실제 테이블 구조를 확인
   - `type_name`이 아닌 `name`이 실제 필드명

3. **권한 체크는 명확하게**
   - Owner/BP 중복 권한 대신 역할별로 명확하게 분리
   - 비즈니스 로직에 맞게 권한 설정
